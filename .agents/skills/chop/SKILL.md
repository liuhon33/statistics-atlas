# chop: one source, one note per topic

Follow `.agents/skills/digest/SKILL.md` from start to finish, with these differences.

1. **Segment.** After securing the originals (digest §2) and reading everything (§3), divide the material by topic. A topic gets its own note only when it needs a different home and has substance of its own: a kept question, a derivation, or a real insight. Fold small tangents into the nearest topic and drop trivial ones. Usually that means two or three notes, never one per question.
2. **Plan each topic:** its message range or section, title, home (full path) or an existing note to `extend`, kept questions, embedded images and connections.
3. **Decide or ask, once.** Show the plan as a short table. If every boundary and home is clear, or the user gave them, write straight away; otherwise ask only the open points, each with your recommendation.
4. **Write** each note as in digest §6. Each note covers only its own segment, and each image is embedded in one note only. Link sibling notes only for a real conceptual reason.
5. **Finish** as in digest §7, with one checkpoint entry for the whole source that lists every segment's boundary and destination, and one Log entry, `chop | <source>`.
