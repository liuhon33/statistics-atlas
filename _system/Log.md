## [2026-11-08] fix | Atlas canvas smeared after a canvas reset (Claude)

User report with screenshot: dots and labels appeared only in a top-left rectangle at half size, and dragging piled lines into a grey smear. Cause, in the original `ui.js`: the high-DPI scale was set once on resize, and each redraw cleared only the width × height region in that scale. When Chromium resets a canvas (a graphics-memory or driver reset, or a display-scale change), the scale drops back to 1. After that, each redraw cleared only 1/dpr of the canvas (dpr 2.25 here) and drew into the shrunken corner. Fix: every paint re-checks size and pixel ratio, resets the transform, clears the whole bitmap, then reapplies the scale. Redraws are coalesced to one per animation frame (dragging used to redraw per pointer event). The canvas also redraws on `contextrestored`. Its `aria-label` became a visually hidden `aria-labelledby` description, because Obsidian shows `aria-label` as a hover tooltip that covered the map. Reproduced in a browser harness with the real vault data at dpr 2.25: the old code showed the shrunken corner and smear, the new code drew a clean map after the forced reset and real drags. Not checked in the running Obsidian app.
